# v2link-client v0.2.4

## Overview

v0.2.4 is a corrective release for Xray-core 26.3.27 compatibility, accurate
optional-helper status, Debian helper hardening, and safer diagnostics. Official
x86-64 AppImage and Debian packages continue to bundle Xray-core v26.3.27.

## Critical Xray compatibility fix

Xray-core 26.3.27 removed the legacy `allowInsecure` configuration field.
v2link-client no longer emits that field. Existing VLESS links containing a false
legacy value continue with normal secure verification; a true legacy value is also
migrated to secure verification and produces a compatibility warning. If the
connection subsequently fails certificate verification, request a current profile
from the service provider.

Configuration validation remains an offline syntax check and does not prove that a
remote service is reachable.

## Modern TLS profile support

The VLESS importer now accepts provider-supplied `pcs` /
`pinnedPeerCertSha256` certificate SHA-256 pins and `vcn` /
`verifyPeerCertByName` certificate verification names. Malformed modern fields are
rejected without echoing their full values. v2link-client never converts a legacy
boolean to a pin, invents a certificate hash, or retrieves a server certificate to
create one.

Saved validation identities now include the generated-config schema and selected
Xray identity, so profiles validated under an older schema are revalidated safely.

## Netmon status and security corrections

The UI now distinguishes whether the optional helper is installed, whether its
daemon is reachable, and whether its backend is operational. An installed but
inactive helper is no longer labelled not installed, and permission, socket,
protocol, kernel and backend failures have distinct states.

The v0.2.4 Rust backend remains an explicit `backend-not-implemented` placeholder.
It is non-operational and supplies no fabricated per-application counters. The
optional Debian service uses a dedicated locked account, a group-only `0660` Unix
socket and no broad Linux capabilities.

## Safe diagnostics and error copying

Diagnostics can be refreshed, copied or saved as a UTF-8 report. The UI also
supports copying the latest actionable error, a profile-validation error and helper
diagnostics. A central sanitizer redacts common profile URLs, credentials, tokens,
identifiers, certificate material and private path components before these values
reach the UI, clipboard, saved reports or normal logs.

Redaction is deliberately conservative and enabled by default, but it is not a
guarantee against every future secret format. Review a report before sharing it
publicly.

## Debian installation notes

The Debian package installs the optional `v2link-netmon` helper and systemd unit but
does not enable or start the service. An administrator may explicitly opt in:

```bash
sudo systemctl enable --now v2link-netmon.service
sudo usermod -aG v2link-netmon "$USER"
```

Log out and back in after group membership changes. Normal proxy operation and
aggregate Xray traffic accounting do not require netmon.

## AppImage notes

The AppImage remains unprivileged and does not contain or install the helper or its
systemd service. It reports that a separately installed system helper is required
for future per-application attribution; this does not indicate a damaged AppImage
and does not block normal proxy operation.

## Known limitation

Production eBPF per-application traffic attribution is deferred to a later release.
While the helper reports `backend-not-implemented`, per-application tracking is not
available. Final eBPF capabilities and service privileges require a separate
security review before that backend is introduced.

## Upgrade guidance

Upgrade by replacing the previous AppImage or installing the v0.2.4 Debian package.
Existing profiles, settings and traffic history are retained. A profile relying on
legacy insecure certificate bypass may need to be replaced with a provider profile
containing valid `pcs` and/or `vcn` data.

## Verification and checksums

Download the AppImage or Debian package together with `SHA256SUMS` from the same
GitHub release and verify it before use:

```bash
sha256sum -c SHA256SUMS
```

The checksum file covers the versioned binary assets. GitHub-generated source
archives are not installable v2link-client binary packages.
