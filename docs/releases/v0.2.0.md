# v2link-client v0.2.0

This release introduces the new Traffic Monitor foundation for local proxy/profile usage history, session analysis, CSV exports, diagnostics, and optional per-application tracking preparation.

## Highlights

- New Traffic Monitor dashboard for local proxy/profile usage history.
- Local SQLite storage for daily totals, profile totals, and session history.
- History drill-down with session details, status reporting, and speed/cumulative charts.
- CSV exports for daily summaries, session summaries, and selected session samples.
- Applications tab and optional `v2link-netmon` helper preparation for future per-application attribution.
- Expanded Traffic Monitor diagnostics for Xray stats, local storage, helper state, permissions, and eBPF availability.

## What’s New

v0.2.0 adds a persistent Traffic Monitor built around Xray Stats API counters and local SQLite storage. The app records proxy/profile upload and download history while Xray is running, groups usage into sessions, aggregates daily/profile totals, and keeps the GUI unprivileged.

The History view now supports date ranges, date drill-down, per-date session lists, selected-session detail panels, and charts for speed or cumulative sample data. CSV export is available for daily summaries, session summaries, and selected session samples.

The Applications tab and `v2link-netmon` client path prepare the UI and data model for optional per-application tracking without claiming that full attribution is always available.

## Traffic Monitor

The Traffic Monitor dashboard includes Overview, Applications, Proxy Profiles, History, Settings, and Diagnostics tabs. Users can review today's upload/download totals, current-session traffic, monthly totals, profile usage totals, daily usage, session history, and detailed session samples.

Traffic Monitor settings include sample retention, summary retention, CSV export, and local history clearing. Proxy/profile tracking works through Xray's local Stats API and does not require root permission.

## Per-Application Tracking Preparation

Per-application tracking is optional and advanced. v0.2.0 includes the `v2link-netmon` Rust helper scaffold, Unix socket JSON API, process identity resolver, SQLite app-usage schema, systemd service packaging, and diagnostics for helper availability, permissions, and eBPF support.

The GUI never runs as root. Debian packages install the optional helper service but do not enable it automatically. If the helper is not installed, not running, lacks permission, or cannot use the required kernel/eBPF capabilities, the GUI reports a clear unavailable state and proxy/profile tracking continues normally.

## Privacy and Storage

Traffic history is stored locally only. The proxy/profile history database is stored at:

```text
$XDG_DATA_HOME/v2link-client/traffic.sqlite3
```

If `XDG_DATA_HOME` is not set, v2link-client uses the platform default data directory, usually `~/.local/share/v2link-client/traffic.sqlite3` on Linux.

Application tracking metadata, when the optional helper path is available, is limited to local process names, executable paths, UIDs, and byte counters. v2link-client does not decrypt traffic, inspect packet payloads, read messages, collect tokens/cookies, or upload telemetry.

## Packaging

Expected release artifacts:

- `v2link-client-0.2.0-linux-<x86_64|aarch64>.AppImage`
- `v2link-client_0.2.0_<amd64|arm64>.deb`
- `SHA256SUMS`

Official AppImage, `.deb`, and APT builds include bundled Xray-core for normal proxy/profile tracking. Debian/APT packages also include the optional `v2link-netmon` helper binary and systemd service.

## Upgrade Notes

Users can upgrade from older 0.1.9.x builds using the new AppImage, by installing the new `.deb`, or through the APT repository if it is already configured.

The optional helper service is not enabled automatically after Debian/APT installation. To enable it:

```bash
sudo systemctl enable --now v2link-netmon
```

To disable it:

```bash
sudo systemctl disable --now v2link-netmon
```

## Known Notes

- Full per-application attribution remains optional/advanced and depends on helper support, permissions, and kernel/eBPF capability.
- AppImage builds do not install or enable the optional helper service.
- Normal proxy/profile traffic tracking works without the helper through Xray's Stats API.
