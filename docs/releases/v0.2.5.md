# v2link-client v0.2.5

This candidate fixes AppImage startup failures caused by missing native Qt/XCB
libraries. It is prepared for review and is not a published release.

## Packaging fixes

- Include and audit the Qt/XCB native dependency closure, including ICCCM,
  cursor, image, keysyms, render-util, XKB and related XCB modules.
- Stop incomplete AppImage builds when a required native library is missing.
- Embed a checksum-pinned official static type-2 AppImage runtime. Host libfuse2
  is no longer required by the runtime; kernel FUSE access is still needed for
  mounting, with extraction-and-run available when FUSE is unavailable.
- Keep glibc and graphics driver libraries on the host; preserve PyQt6's own Qt.
- Add AppStream metadata and runtime/native-library notices.

## Validation and compatibility

CI and release verification now require an actual XCB window that remains alive
for 30 seconds in clean Ubuntu 22.04 and 24.04 environments. The tests run as an
ordinary user, without the missing XCB utility packages installed, and verify
native ELF dependencies plus the bundled Xray binary and configuration.

Official builds target glibc 2.35 or newer (Ubuntu 22.04 / Linux Mint 21 and
newer). The static runtime does not remove the Python/Qt payload's glibc
requirement. Older distributions are outside the supported baseline.

Profile storage and connection behavior are unchanged. Xray-core remains pinned
to v26.3.27. Debian packages, signed APT distribution, TLS verification,
diagnostic redaction and the optional netmon helper's opt-in service lifecycle
are preserved. The netmon backend remains a non-operational placeholder.

## Candidate artifacts

- `v2link-client-0.2.5-x86_64.AppImage`
- `v2link-client_0.2.5_amd64.deb`
- `SHA256SUMS`

Upgrade by replacing the previous AppImage or installing the Debian package.
Existing profile data is retained. Download checksums from the same artifact
set and verify them with `sha256sum -c SHA256SUMS`.
