# v2link-client v0.2.1

This patch release keeps the Traffic Monitor responsive and resource use bounded during long sessions, while strengthening process ownership, shutdown, logging, diagnostics, and regression coverage.

## Highlights

- Bounded background storage and indexed aggregate queries keep SQLite work off the GUI hot path.
- Automatic charts use peak-preserving downsampling and never query or render more than 900 points.
- Ordered, repeat-safe shutdown persists final traffic state and reaps only GUI-owned processes.
- Xray access logging remains disabled by default, and application/Xray logs rotate within documented limits.
- Privacy-safe runtime diagnostics help investigate CPU, memory, database, log, process, and service state without root.

## Long-session Traffic Monitor performance

Live Xray Stats API callbacks now update only in-memory counters and labels. Recurring SQLite writes run through a bounded storage worker, and History, Applications, Profiles, and Diagnostics refresh independently instead of being rebuilt on every live tick.

Only one stats-query child may be in flight at a time. Unchanged history sections and completed session details are cached, long-session tables avoid full sample scans, and automatic session charts use bounded peak-preserving queries. Explicit CSV exports can still read the requested detailed data in the background.

Detailed samples retain a 30-day default with supported bounded choices, while cleanup preserves daily, session, and profile summaries. SQLite connection reuse and retention behavior are covered by dedicated regression tests.

## Process ownership and shutdown

GUI-launched Xray and temporary stats-query commands run in private process groups. Normal stop and application shutdown use bounded TERM-to-KILL escalation and reap only those owned groups.

Shutdown is ordered and idempotent: it stops timers, prevents new jobs, invalidates late callbacks, persists the final cumulative counters, finalises the active traffic session, stops owned processes, restores proxy state owned by the session, and drains the storage worker within bounded waits.

Unrelated system Xray processes are never targeted, and closing the GUI does not stop or restart the independent `v2link-netmon.service`.

## Bounded logging and privacy

Xray access logging remains disabled by default. Xray warnings are written to `xray_stdout.log`, capped at 2 MiB with two backups. Optional detailed Xray diagnostics use the same bounded stream instead of enabling access logs. Python `app.log` rotates at 2 MiB with five backups.

Diagnostics report timings, queue depth, aggregate database counts and sizes, rendered point counts, owned process IDs, proxy backend, and netmon state. They exclude profile URLs, UUIDs, credentials, tokens, command arguments, environment variables, and private configuration contents.

## Runtime diagnostics

The new `scripts/diagnose_runtime_performance.sh` helper is read-only, requires no root privileges, and reports safe process columns, CPU/memory/resource state, database/WAL/log sizes, optional aggregate SQLite counts, and `v2link-netmon.service` state. It never kills processes or changes proxy settings.

See `docs/runtime-performance-troubleshooting.md` and `docs/traffic-monitor.md` for thresholds, retention behavior, ownership rules, and investigation guidance.

## Testing and documentation

This release adds focused regression coverage for:

- Traffic Monitor live-callback and long-session hot paths.
- Bounded storage, retention cleanup, SQLite connection reuse, and query behavior.
- Chart point limits and peak-preserving downsampling.
- Xray Stats API concurrency and temporary child ownership.
- Ordered and repeated shutdown, proxy restoration, and unrelated-process safety.
- Logging bounds, privacy-safe diagnostics, build scripts, and bundled Xray discovery.

Developer and operator documentation now records the performance invariants, safe source workflow, packaging checks, runtime diagnostics, and shutdown ownership model.

## Packaging

Official release artifacts are:

- `v2link-client-0.2.1-linux-<x86_64|aarch64>.AppImage`
- `v2link-client_0.2.1_<amd64|arm64>.deb`
- `SHA256SUMS`
- The signed APT repository update

The AppImage and Debian package bundle the pinned Xray-core binary plus `geoip.dat` and `geosite.dat`. Debian/APT packages also include `v2link-netmon`, its systemd service, the desktop launcher, and application icon.

## Upgrade notes

Users can upgrade from v0.2.0 using the AppImage, by installing the `.deb`, or through the signed APT repository. Existing Traffic Monitor databases are migrated in place, and cleanup preserves aggregate session, daily, and profile history.

The optional netmon service remains independent and is not enabled or stopped by normal GUI lifecycle actions.
